# A 组 · 高危（大概率在这里出问题）

## A1 · ✦ 按钮是否出现在输入框右下角

- [ ] 通过

**前置**
DSH 已完全重启；插件为启用状态。目标位置是输入框工具行、发送按钮与模型选择器之间的那个四角星位置。

**操作**
1. 打开任意会话，目光落在输入框底部工具行。
2. 把鼠标移到 ✦ 上悬停，不要点击。

**通过标准**
- 该位置出现**两个**按钮：带文字的主按钮「✦ 优化提示词」，以及紧挨着的齿轮按钮「⚙」（悬停提示「优化设置」）。
- 主按钮的文字会随状态变：idle「优化提示词」→ 加载中「优化中…」（图标换成转圈）→ 完成后「还原原文」（图标换成 ↺）。
- 输入框为空或只有空白时主按钮 disabled 观感，输入文字后变为可点。

**不通过先查**
按顺序排查，每步都记录现象：
1. **槽位被占**——`conversation.input.activity` 是 single 槽，一个包只能占一条。
   历史事故：`@deepseek-ai/dsh-experimental-voice-input-bundle` 装回来会把 ✦ 挤掉。
   查 `C:\Users\23897\.dsh\profiles\desktop\node_modules\@deepseek-ai\` 下是否又出现 voice-input / auto-review 相关包。
2. **宿主是否装载**——profile 的 `package.json` 里 `bundles` 清单是否含 `dsh-plugin-prompt-optimizer`；
   `node_modules\dsh-plugin-prompt-optimizer` 是否是指向工作区的 SymbolicLink。
3. **组件是否抛错被隔离**——打开 DSH 的开发者工具看 console，找插件 id 相关的红字。
   最常见根因是 `ctx.slots.register` 少了 `store` 座位，组件拿不到 `props.useStore` 直接抛错，条目被静默隔离。
   对应源码：`src/client/index.js:29-30` 的 `name: "conversation.input.activity"` 与 `src/client/index.js:41` 的 `ctx.slots.inject(...)`。
4. **是否只是没重启**——重来一次完全退出再启动。

- [ ] 通过

**前置**

**操作**

   写成 `1fr 1fr` 时 `1fr` 的最小尺寸是 `auto`，长文本会把列撑开。
3. 白底白字查颜色是不是又用了**宿主不存在的 CSS 变量**。
   宿主确实定义了 `--dsw-alias-bg-module-platform` / `--dsw-alias-label-primary` / `--dsw-alias-border-l1` / `--dsw-alias-state-error-primary`；

## A3 · 本地引擎全链路：加载态 → 回填 → 可撤回

- [ ] 通过

**前置**
A1/A2 通过；设置里 `engine = local`（引擎选「本地」），`mergeMode = strict`。

**操作**
1. 在输入框里输入一段**故意啰嗦**的中文提示词，例如：
   「嗯，就是那个，我想让你帮我写一个 Python 脚本嘛，它要去读一个 csv 文件，然后呢把里面每一行的第二列加起来，最后输出出来，对了要处理一下那个空的单元格，别让它报错」
2. 点 ✦。观察按钮状态。
3. 等待完成后看对比面板，然后撤回：可以直接点已经变成「还原原文」的主按钮，
   也可以点完成小条 / 对比面板里的「还原原文」按钮（两处入口效果必须一致）。
4. 还原后再点主按钮重来一次，确认新一轮结果不含上一轮残留。

**通过标准**
- 点击后**立刻**出现加载态（按钮禁用 + 有可感知的进行中文案/转圈），不是点完没反应。
- 加载态期间输入框里的原文**一个字都没变**。
- 完成后原文被替换为结构化五段（角色 / 任务 / 上下文 / 输出要求 / 约束），空段显示占位符而不是消失。
- 对比面板左栏是**原文逐字**、右栏是优化结果。
- 点「还原原文」后输入框回到**逐字**原文（包括错别字与标点，不是「差不多」）。
- 还原后再优化一次，结果不会叠加两份内容。

**不通过先查**
1. 加载态由 `src/client/button.js` 控制，无障碍播报在 `:850`（`role="status"` + `aria-live="polite"`，忙碌时文案「正在优化提示词」）。看不到视觉加载态但屏幕阅读器有播报，说明只是样式问题。
2. 「原文被改动」查唯一的写回点：`src/client/button.js` 里的 `function writeResult(token, text, extra)`。校验兜底也在这个函数内、写回之前，所以**任何写回都必须经过它**；若发现别处直接 `inputActions.setDraft`，即为越界改动。
3. 「还原不逐字」查 restore 是否保存了原文快照而不是「优化后再反向推理」。
4. 「叠加」查令牌守门（`runRef`）：一次点击一个令牌，过期令牌的写回应被丢弃。

## A6 · 测试连接的四类失败与一类成功

- [ ] 通过（可按勾选数拆成多条）

**前置**
A4 中已有一条**故意配错**的模型。

**操作**
按顺序造四种失败，每种点一次设置面板里的「测试连接」：
1. 正确地址 + 错误密钥（期望上游 401/403）。
2. 错误路径（例如把 `/chat/completions` 写成 `/chat`，期望上游 404）。
3. 不可达地址（例如 `http://127.0.0.1:1/v1/chat/completions`，期望连不上）。
4. 超时（把 timeoutMs 调到 5000，指向一个会挂住的地址）。
最后用一条正确配置点一次，期望成功。

**通过标准**
- 测试中按钮转圈且不可重复点。
- 成功显示绿字「连接正常 · <毫秒>ms」。
- 失败文案是「连接失败 · <分类>」，四种失败应分别落到下列**具体**文案（不是一句笼统的「失败」）：
  - 401/403 → `连接失败 · 401 密钥无效`
  - 404 → `连接失败 · 404 路径不对`
  - 不可达 / 网络断 → `连接失败 · 地址不可达`
  - 超时 / 408 / 504 → `连接失败 · 超时`
  - 宿主未登记（501）→ `连接失败 · 宿主未登记该模型，请先保存后再测`
- **任何情况下都不显示密钥**。
- 测试不会改动模型配置、不会改动输入框原文。

**不通过先查**
1. 客户端拿不到上游真实状态码，因为宿主把上游非 2xx 统一包成了 502 + 固定文案：
   `src/host/index.js:838` `if (!response.ok) return jsonResponse({ error: \`上游返回 ${response.status}\` }, 502);`
   客户端靠正则从这句文案里把码抽回来（`src/client/settings.js:507` 附近），这是**隐式耦合**，已知限制第 7 条有记录。
   若分类错乱，先确认宿主这句文案没被改。
2. 分类函数是 `src/client/settings.js:521` 的 `classifyTestFailure`，结论文案在 `:542` 的 `summarizeTest`。
3. 测试连接**走的是同一条优化路由**，只发一个 `text:'ping'`；宿主侧自己构造上游请求体。所以客户端无法指定上游参数，这是有意的安全设计，不是 bug。

## A7 · LLM 通路端到端（走宿主转发）

- [ ] 通过

**前置**
A4 有一条可用模型且已设为默认；A6 的成功项已过；设置面板「引擎」选 `auto`（默认档）或显式 `llm`。

**操作**
0. 先确认档位：设置面板「引擎」是 `auto` / `local` / `llm` 三档分段控件，**`auto` 排在首位**且是默认档；选 `auto` 时只要表里有默认模型，`resolveEngine` 就当场按 `llm` 走。
1. 输入一段普通提示词，点 ✦。
2. 观察是否走宿主（不是本地规则）：小条出现「LLM 走宿主通路（/api/prompt-optimizer/optimize），按默认模型转发…」即说明真的走了上游。
3. 完成后再打开设置面板，把默认模型删掉，然后回到输入框再点一次 ✦。

**通过标准**
- 走 LLM 时，结果按三档强度里当前所选的一档产出（light 只去口语填充、standard 结构化为五段、deep 允许补推断但必须单独写进「### 其他（推断补充，请确认）」）。
- 界面明确标注这条通路走宿主（文案含「LLM 走宿主通路」）。
- 引擎为 `auto` 且表里有默认模型时行为等同 `llm`（这一步应真的走向上）；把默认模型删掉后 `auto` 立刻退化成 `local`——同一次验收可同时证这两步。
- 删掉默认模型后再点：**自动回退本地引擎**并给出提示，不是直接报错或卡住。
- 整条链路上，请求体里**不会**出现 endpoint / apiKey / model 这三个字段（它们由宿主从自己的表里取）。

**不通过先查**
1. 回退逻辑在 `src/client/settings.js:403` 的 `resolveEngine`：`engine=llm`（或 `auto`）但表里没有 isDefault 时回落 local；`auto` 的定档也发生在这一处（有默认模型 → `llm`，没有 → `local`），所以面板上显示的档位可能已是解析后的结果，而不是字面的 `auto`。
   注意宿主**不保证**表里至少有一条 isDefault（已知限制第 4 条），所以这条回落是必需的。
2. 宿主未配置模型时优化路由返回 501 `{error:'llm endpoint not configured'}`。
3. 安全边界：上游地址只来自宿主模型表或 patch config 的 `llmEndpoint`，请求体里的 URL 会被丢弃并在响应里回 `ignoredFields`。这是 SSRF 边界，如需确认可看 `src/host/index.js` 顶部的注释。
4. 打包产物里 **`fetch` 调用只允许有一处**（`src/client/llm.js` 内的 `requestJson`）。`scripts/verify.mjs` 有一条断言守这个；如果这里发现第二条网络出口，属安全回归。

# C 组 · 低危（呈现细节，不影响主流程）

## A8 · 守恒校验的两档呈现

- [ ] 通过

**前置**
A3 通过。构造一段包含硬 Token 的提示词（数字、URL、@引用、行内代码、全大写标识符各来一个）。

**操作**
1. `mergeMode = strict`，优化一次，看是否出现校验警示块。
2. `mergeMode = lenient`，同样内容再优化一次，对比差异。
3. 把输入框清空 / 粘贴超过 20000 字符，各点一次 ✦。

**通过标准**
- strict：**文本不被改写**（原文在，只是优化结果做校验），若校验不过给**非阻塞**警示，可展开看到丢失的原句列表与丢失的硬 Token。
- lenient：丢失的句子被补回到结果末尾的 `### 其他` 段，每一条都带 `(未归类，请确认)` 标注；提示语气比 strict 轻。
- 校验通过时**完全不占位**（不显示空白的警示块）。
- 校验引擎自身出错时，界面不炸：退回「不校验、原样展示」，不阻断优化主流程。
- 空输入：按钮 disabled，点不动。超长输入：给出明确上限提示且不覆盖原文。

**不通过先查**
1. 校验兜底唯一入口 `src/client/engine.js` 的 `applyGuard(originalText, resultText, mode)`；
   它在 `src/client/button.js` 的 `writeResult` 内、写回之前被调用一次。
2. 报告形状固定为 `{ok, dropped[], lostTokens[], sectionValid, details[], uncategorized, reassigned[], compensated, recheckOk}`；
   呈现组件是 `src/client/overlays.js` 的 `ConservationBlock`，容器类 `.dsh-po-guard`，带 `data-dsh-po-level`（warning / info）。
3. 「改判 N 条」这个计数是在**结果文本**上重跑归并算出来的，语义只是「结果内的重排」，不要当成「原文被改判了几何」（已知限制第 2 条）。

1. 在 done 状态（结果显示后）**连点**主按钮两次（此时它显示「还原原文」）。
2. done 后先点「还原原文」，再点主按钮一次。
3. 优化完成后改强度档位，再点一次 ✦。
4. 优化过程中（加载态）切换强度。

**通过标准**
- 连点不会叠加两份结果，也不会让状态卡在 loading。
- 还原后再优化，结果里不含上一次的残留。
- 改强度后重跑，新结果按新档位产出（light 与 deep 的差异应当肉眼可见）。
- 加载中改设置：要么被忽略并给提示，要么在完成后生效，**不能出现半新半旧的结果**。

**不通过先查**
1. 幂等的守门是一次点击一个令牌（`runRef`），只有当前令牌能写回。
2. 加载中草稿被用户改动是一条**专门的失败路径**（令牌失效 → 放弃写回 + 明确提示），不是异常，属预期行为。
3. 若状态卡死，先看 `.dsh-po-toast` / `.dsh-po-error` 两个浮层是否有残留节点没被卸载。
