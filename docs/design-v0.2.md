## 0. 先摆三个会决定实现方式的现状事实

**事实 1 — 强度选项对 LLM 通路当前是失效的。** `lib/index.js:42-55` 的 `SYSTEM_PROMPT` 是固定常量，
注释明写「强度/语种不参与改写这段文本」；`src/client/llm.js:61-68` 的 `requestPayload()` 虽然把
`strength` / `locale` 放进了请求体，但宿主侧没有把它们拼进 prompt。所以设置面板里的「轻/标准/深度」
只对本地引擎生效。**v0.2 必须修**，否则新增的设置面板会变成一堆不生效的开关。

**事实 2 — 宿主只认单一 `llmEndpoint`，且该地址只来自 patch config。** `lib/index.js:26` 的
`CONFIG_FIELDS` 白名单 = `llmEndpoint / llmApiKey / llmModel / llmTemperature / llmTimeoutMs`，
`lib/index.js:102-103` 会拒绝任何未知字段。多模型配置不可能塞进这单一字段。

**事实 3 — 宿主当前有一条明确的安全边界：请求体不参与拼地址（防 SSRF）。** `lib/index.js:8-13` 写着：
「上游地址**只来自 config.llmEndpoint**，请求体里的任何字段都不参与拼地址 —— 否则这条路由就是一个
任意 URL 代理（SSRF）」。你选定的「配置存 localStorage、改完即时生效」与这条边界**正面冲突**：
要让 UI 里的地址立刻可用，客户端就必须把地址传上来，宿主就只能信任客户端。这是本方案唯一需要
你再次拍板的地方，见第 5 节。

## 1. 产出物一：字段清单

### 1.1 模型条目（`models[]`，每条一个 API）

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|---|---|---|---|---|
| `id` | string | 是 | uuid v4，列表内唯一 | 内部标识，UI 不展示 |
| `name` | string | 是 | 1–40 字符，去首尾空白 | 显示名，留空时自动取 `model` |
| `endpoint` | string | 是 | 绝对 URL；只允许 http/https；不含用户名密码；不含 query/fragment | 完整到 `/chat/completions`，不自动拼接 |
| `apiKey` | string | 是 | 1–512 字符，不 trim 内部空白 | 存 localStorage，明文（你选的 A 方案） |
| `model` | string | 是 | 1–120 字符 | 如 `deepseek-chat`、`gpt-4o-mini` |
| `temperature` | number | 否 | 0–2，默认 0.2 | 越界按边界截断 |
| `timeoutMs` | number | 否 | 5000–120000，默认 30000 | 越界按边界截断 |
| `isDefault` | boolean | 否 | 全表至多一条为 true | 由「设为默认」维护，不手填 |
| `createdAt` | number | 是 | 时间戳 | 排序用 |
| `updatedAt` | number | 是 | 时间戳 | 显示「最近修改」 |

### 1.2 全局设置（`settings`，从现有 `config` 键升级而来）

| 字段 | 类型 | 取值 | 现状 |
|---|---|---|---|
| `strength` | string | `light` / `standard` / `deep` | 已有，但需真正接进 prompt（事实 1） |
| `locale` | string | `zh` / `en` | 已有，同上 |
| `engine` | string | `local` / `llm` | 已有 |

| `schemaVersion` | number | 固定 `2` | **新增**，用于旧配置迁移 |

### 1.3 校验兜底报告（优化结果附带，供对比面板展示）

| 字段 | 类型 | 含义 |

### 2.1 界面要素

浮层沿用现有 `.dsh-po-panel`（宽度上限 620px，v0.1.1 已修），内部改为两段式：模型 API 列表 + 优化行为。

```
│     sk-…a1b2 · 最近修改 10-21 16:30        │
│                [测试] [编辑] [删除]         │
│   ○ 本地 Ollama     qwen2.5:7b             │
│     未设密钥 · http://127.0.0.1:11434      │
│  [ + 添加模型 ]        共 2 条 / 上限 20    │
│                                            │
│ 优化行为                                    │
│  强度   (轻) (●标准) (深度)                 │
│  语言   (●中文) (英文)                      │
│  引擎   (●本地) (LLM·默认模型)              │
│  校验   (●严格) (宽松)                      │
│                          [关闭]  [保存]     │
└────────────────────────────────────────────┘
```

### 2.2 五个动作的流程

**添加**
1. 点「+ 添加模型」→ 列表下方展开空表单（不弹二级窗，避免浮层套浮层）。
2. 字段：显示名 / API 地址 / 密钥 / 模型名 / 温度 / 超时。
3. 失焦即时校验，错误显示在字段下方（红色小字），保存按钮保持禁用直到全部通过。
4. 保存 → 追加到列表尾 → 若当前无默认模型，自动设为默认。
5. 达到上限 20 条时「+」禁用并提示「最多 20 个模型」。

**编辑**
1. 点「编辑」→ 该行原位展开表单，字段预填。
2. 密钥字段显示掩码 `sk-…a1b2`（只露末 4 位）；点击输入框才切到明文编辑，未修改则提交时沿用原值。
3. 保存即写 localStorage，**不需要重启 DSH**（这是选 A 方案换来的核心收益）。

**删除**
1. 点「删除」→ 行内二次确认（「删除后不可恢复」+ [取消] [确认删除]），不做模态框。
2. 删除的是默认模型时：自动把列表首条设为默认；若删空，`engine` 强制回落 `local` 并提示。

**切换默认**
1. 点行首单选圆点 → 立即生效（写 `isDefault`，其余置 false）。
2. 若 `engine === 'local'`，切换默认时提示「已设默认模型，是否切换到 LLM 引擎？」提供一键切换。

**测试连接**（直接回应你说的「避免设置后难以更改」）
1. 点「测试」→ 按钮转圈，发一条最小请求：`messages:[{role:'user',content:'ping'}]`、`max_tokens:1`。
2. 成功：行尾绿色「连接正常 · 320ms」。
3. 失败：红色 + 具体原因（地址不可达 / 401 密钥无效 / 404 路径不对 / 超时），原样显示 HTTP 状态码，不显示密钥。
4. 测试走的就是真实优化通路，测通即代表能用。

### 2.3 持久化与迁移

- 新键：`dsh-plugin-prompt-optimizer/models`（`{ schemaVersion: 2, models: [...], settings: {...} }`）。
- 旧键 `dsh-plugin-prompt-optimizer/config` 保留只读：首次打开新面板时若有内容，顶部显示一条可关闭提示
  「检测到旧版配置，是否导入为一个模型条目？」→ [导入] / [忽略]。
- 写入失败（无痕模式、配额满）：顶部黄条「配置未能保存，关闭后将丢失」，内存值继续可用。
- 读取损坏：整体回落默认值，并把损坏内容原样挪到 `.../models.corrupt` 键供事后手工捞取，不静默丢弃。

## 4. 产出物四：归并规则表

### 4.1 栏目与识别信号

栏目固定为 **角色 / 任务 / 上下文 / 输出要求 / 约束**，另有兜底栏 **其他**。

| 栏目 | 高置信信号（命中即归入） | 低置信信号（需结合句式） |
|---|---|---|
| 角色 | 「你是」「扮演」「作为…」「你的身份」 | 职业/角色名词且句首为第二人称 |
| 任务 | 「请」「帮我」「实现」「生成」「分析」「写一个」「改造」 | 祈使句、动宾结构开头 |
| 输出要求 | 「格式」「字数」「长度」「用…语言」「表格」「JSON」「Markdown」「分点」「列出」「返回结构」 | 含「要/需/应该」+ 产出物名词 |
| 约束 | 「必须」「不得」「禁止」「只能」「不要」「务必」「仅限」「最多」「至少」「保留」「不得改变」「原样」 | 否定句、上限下限表达 |
| 上下文 | 「背景」「已知」「材料」「参考」「根据」「输入是」「用户是」「当前」 | 陈述客观事实而非命令的句子 |

### 4.2 优先级归并规则（同时命中多栏时）

```
命中集合 → 按 约束 > 输出要求 > 上下文 的优先级取首个匹配栏目
         → 若只命中 角色 / 任务 之一，直接归入（这两栏不参与优先级竞争，信号独立）
         → 一个都不命中 → 归入「其他」，并加标记「(未归类，请确认)」
         → 每条原文整句保留，不改写、不合并、不省略
```

**为什么角色/任务不参与优先级**：它们由人称与句法决定（第二人称陈述=角色，祈使句=任务），
和「约束/输出要求/上下文」是不同维度，放进同一优先级比较会互相抢句子。

### 4.3 内容守恒校验（本方案核心，防「归并丢东西」）

LLM 产出的结果必须通过三道校验，任一道不过即按 `mergeMode` 处理：

| 校验 | 方法 | strict 失败处理 | lenient 失败处理 |
|---|---|---|---|
| 句子守恒 | 原文按 `。！？；` 与换行切句，逐句先在结果中做字面查找；未命中的非代码围栏句按 2–4 字实义片段覆盖率判定，低于 0.6 才判丢失（见第 9 节第 7 条：口径已从「字面子串」演进为「硬 Token + 软覆盖率」两层） | 整单回退，提示「有 N 处内容未能保真」 | 缺失句补进「其他」栏并标注 |
| 硬 Token 守恒 | 提取数字、URL、@引用、行内代码、全大写标识符，逐个比对 | 同上 | 同上，并在对比面板标红 |
| 栏目合法性 | 结果必须恰好含五个 `### ` 段头，段名与顺序固定 | 整单回退 | 缺失段补空并在「其他」栏说明 |

### 4.4 润色与精确化的边界（强度分级）

| 强度 | 允许的改动 | 禁止的改动 |
|---|---|---|
| `light` | 去口语填充词、补标点、修正明显病句 | 改动句式结构、增删信息 |
| `standard` | 上述 + 按 4.2 重排为五段 + 模糊表述具体化 | 新增原文没有的要求、删减任何原句 |
| `deep` | 上述 + 补全隐含前提与缺失字段，但必须写在「### 其他（推断补充，请确认）」 | 把推断内容混进正文而不标注 |

## 5. 需要你拍板的一个技术权衡（与事实 3 冲突）

你选了「配置存 localStorage、即时生效」。要让 UI 里新加的地址立刻可用，只有两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（实现简单）** | 客户端每次请求把 endpoint/apiKey/model 传给宿主，宿主只做格式校验（绝对 URL、http/https、无凭据、无 query）后转发 | `lib/index.js:8-13` 的 SSRF 边界失效：这条同源路由变成「能传任意 URL 就会代理任意 URL」。缓解：路由仅同源可达、不放开 CORS |
| **B（安全优先，推荐）** | 宿主新增 `POST /api/prompt-optimizer/config` 写配置路由，前端把模型表交给宿主持久化，宿主持有地址白名单；localStorage 只存 UI 偏好 | 实现量 +1 个宿主路由 +1 个配置文件；「即时生效」仍成立（不需重启），只是存储位置从 localStorage 挪到宿主 |

**我的建议：选 B。** 你要的是「随时可改且立即生效」，B 同样满足；而 A 把一个本来严丝合缝的安全边界
换成「谁都能让宿主代理任意地址」，为一个本地插件的便利性不值得。若你仍选 A，我会在 README 与设置面板里显式写明风险。

## 6. 假设清单（你没说、我按此默认）

1. 「任务栏内容」= 输入框当前草稿，不是已发送的消息或计划任务卡片。
2. 模型 API 走 OpenAI 兼容的 `/chat/completions` 协议；非兼容协议（如 Anthropic 原生）不在本期范围。
3. 模型条目上限 20 条。
4. 不引入流式输出：优化结果一次性返回（现有通路即如此）。
5. 密钥不明文回显，只露末 4 位；不写日志、不进对比面板的复制内容。
6. 「其他」是显式存在的第六段，段名固定 `### 其他`，仅在有条目时输出。
7. 旧 patch config 的 `llmEndpoint` 等字段保留兼容：若存在且 localStorage 无模型，自动视为一条只读模型条目。

## 9. 实施记录（as-built）

本节只记**实际实现与上述设计的差异**及原因。前 8 节保持原样未改。

1. **模型表真源在客户端 `localStorage`**（设计 2.3 只写了「持久化」）。宿主 `GET /api/prompt-optimizer/models` 返回的 `apiKey` 已掩成 `sk-…ab12`（`src/host/index.js:526-531`），回写必毁真密钥，故客户端只读不回写；代价是多设备不同步（见 known-limitations 5）。
2. **宿主不保证表内有一条 `isDefault`**（设计 2.2 假设客户端总会维护默认项）。宿主 `normalizeHostModels` 只做条目级归一化，`engine=llm` 且无默认项时由客户端回落到本地并提示（`src/client/settings.js:325-336`）。
3. **宿主对 21 条整体拒绝（400），不截断**（设计假设 3 只说「上限 20」）。客户端 `normalizeModelList` 是截断、宿主是拒绝：静默截断会丢用户数据，宿主选了显式失败（`src/host/index.js:329, 888-889`）。
4. **`mergeMode` 落进 `settings` 四键**（设计 1.2 原把它当独立校验开关）。它和 strength/locale/engine 一样是「行为设置」，同一份 `normalizeConfig` 归一化、同一处落盘，少一套存储路径。
5. **守恒校验在客户端做，宿主只回 `{ok, text}`**（设计 4.3 未指定归属）。宿主不该理解文案结构，且 `local` 引擎全程不经过宿主——校验若放宿主，本地通路就没有兜底。实现在 `src/client/engine.js` 的 `applyGuard`，写回前唯一一次。
6. **打包器需把 `src/engine/merge.js` 加进 `ENGINE_FILES` 白名单**（设计未提构建）。`scripts/build.mjs:30` 的白名单同时是「可内联源文件」的准入名单，不加则客户端 `getMerge()` 永远为 null、`applyGuard` 恒降级为「不校验、原样展示」——静默失效，无报错。
7. **守恒口径从「字面子串」改成「硬 Token + 软覆盖率」两层**（设计 4.3 原写「逐句在结果中做子串查找」）。旧口径有两个反向后果：①只要结果里出现「原文原句为…」就整句命中，于是「上下文」段被写成复述反而不判丢失——校验在反向激励模型抄原文；②一旦允许多改写表达，旧口径会把每次正常改写真报成「内容未能保真」。现在硬层（数字、URL、@引用、行内代码，以及按**极性词族**计次的否定词）零容忍，软层按 2–4 字实义片段覆盖率 `SOFT_COVERAGE_THRESHOLD = 0.6` 判定，代码围栏仍整块字面零容忍。另 `applyConservation` 增加了**段头兜底**：结果缺 `### ` 段头时按 `SECTION_ORDER` 补齐并写 `- （无）`、记进 `report.details` 与 `report.backfilled`——旧实现里结构不合格在 strict 下是原样返回残缺结果（实测四段结果照样交付用户），等于没有兜底。残余风险见 known-limitations 12、13。
